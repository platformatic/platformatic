Release recommendation: **hold**. This is an opt-in implementation for review; production per-app SLOs, error budgets, resource limits and a canary destination have not been established. Performance results must not be treated as a promise of improvement over other gateways.

Two existing scaler defects are fixed: candidate ELU is now stored under the field used by the ordering comparator, and old metrics expire after the intended window instead of 1,000 times later. Three regressions fail before and pass after; all 44 scaler unit/integration tests pass. Production head `280608ce9` has 242 successful CI checks and one neutral check. The 800 ms threshold is diagnostic, not a supplied production SLO.

Keep round robin as the default and prioritize app allocation plus per-app overload protection. The new supervisor sampler, timing hooks, ELU preferences and pilot limits are benchmark-only. Across all policies/cohorts, 4,500 arrivals fail, including 3,222 admission rejections; none are removed from denominators. No OOM or remaining reservations were observed. The public least-outstanding implementation remains opt-in and the release remains on hold; the earlier transport/frontend, confidence and canary gates below are still open. ## Implemented contract

An internal application's `requestRouting.algorithm: "least-outstanding"` selects among that application's ready mesh workers for each HTTP request. Requests on a persistent HTTP/1 connection and concurrent HTTP/2 streams select independently. Round robin remains the default.

The runtime creates fresh shared state for each backend generation. Bounded reservation slots and unique 64-bit leases provide admission across multiple callers without a global lock. Selection reads an approximate outstanding snapshot; reservation slots enforce the hard bound. Drain blocks new reservations permanently for that generation, including late readiness updates. Backend exit retires its state; replacement workers receive different state.

Completion means backend response production ended, closed or failed. Timeout, client disconnect or gateway exit alone does not release accepted backend work. The transport holds accepted work until backend completion or actual backend exit. Unaccepted claims from a dead caller are reconciled by the backend actor. Long-lived streams occupy capacity. Work outside participating HTTP dispatchers, including background CPU jobs, is not represented.

The maintained mesh source originates from MIT-licensed `undici-thread-interceptor` 1.5.0. Its license is included in the published runtime. This avoids relying on an unpublished dependency API or consumers applying a package-manager patch. It adds three direct JavaScript dependencies already used by the upstream transport; it introduces no SQLite or native memory-map dependency.

The public policy rejects entrypoints, `useHttp`, TCP/subprocess targets and the application's WebSocket flag. TCP connection distribution and request selection have different lifecycle information. The experimental ELU/heap preference exists only as a benchmark comparator; it is not accepted by the configuration schema.

Admission exhaustion returns HTTP 503 with `PLT_REQUEST_CAPACITY_EXCEEDED`. The gateway does not automatically replay that rejection. Existing retries for other responses are preserved. Worker details and generation-labelled metrics expose outstanding reservations, selections, releases, rejections and invalid reservation messages. Abrupt termination may interrupt cumulative bookkeeping; the current outstanding gauge is the load signal.

## Performance and rollout gates

The current production source completed 108 valid fixed-worker multi-app cases with 139,878 planned arrivals, zero response errors and no remaining reservations. The five-seed primary rendering p99 medians were 801.9/805.4 ms for round robin/least outstanding on HTTP/1 and 805.6/803.5 ms on HTTP/2. The experimental pressure preference was worse: 1491.2/1100.8 ms. This does not demonstrate a repeatable scheduling benefit. All per-app outcomes, variation, resource use and health samples remain in the raw cohort.

The latest seven-seed short forwarding cohort uses the rebased production source. Least outstanding measured 115.99%/112.46% of pristine stock HTTP/1/HTTP/2 median throughput, but bootstrap 95% lower bounds of 94.958%/79.498% fail the proposed 95% confidence gate. Maintained round robin measured 103.97%/116.96%, also with wide intervals. These are separate from the earlier pre-rebase cohort. A prospectively declared steady-state cohort uses seeds 8–14, 15 seconds warmup and 60 seconds measurement; no gate or outlier policy changes.

The fixed campaign is `release-v17-calibrated`. Its six scaler-labelled cases omitted runtime-wide `workers.dynamic: true` and are excluded from scaler evidence. All six corrected `release-v18-scaler` cases pass with 26,244 arrivals, zero errors and no remaining reservations. They run that switch, record every unmodified recommendation and worker-generation event, and observe catalog/search scale-down and rendering scale-up. Rendering median p99 is 599.2 ms round robin versus 614.7 ms least outstanding. The separate `release-v18-steady-forwarding` cohort is complete, with zero response errors or remaining reservations in all 42 runs. Least outstanding measured 113.11%/95.09% of stock HTTP/1/HTTP/2 median throughput; 95% confidence lower bounds were 79.817%/77.759%. Longer warmup/measurement did not resolve repeatability. The overhead confidence gate remains unmet. Production routing source is unchanged from `dd9c49ed64eeee5fc918cf1e72eac3cd807a403d` across these cohorts. Actual deployed/loaded source hashes, configurations, arrivals, every terminal outcome, health samples, GC observations and logs are under `results/review/multi-app/`. The Docker VM hosts unrelated services; variation remains visible. Nginx is excluded.

Run `BENCH_WORKSPACE=/work python3 review/multi-app/campaign.py --revision <unique-revision>` after `setup.sh` in a clean checkout. Run capacity experiments serially and after correctness tests finish. The development overlays used `/focused` instead of `/work`.

Do not promote this draft until the latest campaign demonstrates a repeatable benefit without an unacceptable cost to any app, the overhead gate passes, production SLOs/resource budgets are supplied, and a representative canary exercises normal load variation and worker replacement. The multi-app TCP/Rust comparison remains separate work; the existing single-app prototype measurements do not satisfy it. Disabling `requestRouting` and restarting returns to round robin; validate that rollback during the canary before rollout.

The recorded gateway plugin’s encapsulated request hooks did not observe proxy routes. Gateway request counters and identity headers in v17/v18 are unavailable; its global per-thread ELU/heap/GC and backend identity/accounting data remain valid. The fixture is corrected for new runs; all twelve separate HTTP/1/HTTP/2 validation cases passed, with valid gateway identity on all 1,260 responses and advancing served counters. The single-connection HTTP/2 frontend variants do not demonstrate multi-gateway throughput scaling.

The complete release evaluation and compact machine-readable results are in `REPORT.md` and `evidence/multi-app-results.json`. The plan remains incomplete: no repeatable primary scheduling benefit, no stable overhead confidence gate, no matched-load cohosting/frontend capacity or multi-app TCP/Rust contract comparison, and no production SLO/canary/rollback evidence.
